# Результаты реальных проверок

Сценарий: `tests/integration.py`. Время каждого события в `integration-results.json` записано в UTC. Успех определяется проверками ответов и состояния контейнеров, а не наличием файлов конфигурации. В текстовых логах удалены только конечные пробелы строк и BOM для чистого Git diff.

| Файл | Что подтверждает |
|---|---|
| `docker-build.txt` | Фактическую сборку и запуск финальной конфигурации Gateway |
| `docker-compose-ps.txt` | Пять запущенных healthy-контейнеров перед тестами |
| `docker-compose-ps-final.txt` | Состояние после восстановления контейнеров |
| `runtime-versions.txt` | Версии Docker Engine и Compose |
| `auth-installed-packages.txt`, `catalog-installed-packages.txt` | Фактически установленные пакеты в образах |
| `consul-services.json` | Имена, адреса и порты зарегистрированных сервисов |
| `consul-checks.json` | HTTP-проверки Consul со статусом passing |
| `consul-lifecycle.txt` | Регистрацию, дерегистрацию и повторы при недоступности Consul |
| `nginx-requests.txt` | HTTP-статусы и адреса upstream; переключение на второй адрес |
| `integration-results.json` | JWT, отрицательные сценарии, CRUD, балансировку, отказ и восстановление |

В журнале Nginx во время преднамеренного отказа встречается `upstream_status=504, 200`: первая попытка соединения не удалась, вторая успешна, клиент получил **200**. Аналогично POST, который не был отправлен первому серверу, может иметь `504, 201`. Повторы уже отправленных неидемпотентных запросов не включены.

Предупреждения Consul в период его преднамеренной остановки ожидаемы. Если Consul выключен, подтвердить дерегистрацию через его API невозможно; код выполняет ограниченные повторы. Штатная дерегистрация при работающем Consul проверяется отдельно.

JWT и `SECRET_KEY` в материалы не записываются. Сохранён ответ `/me` и результат проверки подписи, а не сам токен. Скриншоты не подменяются текстовыми имитациями; точный список кадров для ручной съёмки находится в `DEFENSE_GUIDE.md`.

При повторном запуске теста его JSON и снимки состояния перезаписываются. Полные журналы и список пакетов относятся к сохранённому запуску; для нового отчёта их следует получить заново через `docker compose logs --no-color` и `docker compose exec -T SERVICE python -m pip freeze`.
